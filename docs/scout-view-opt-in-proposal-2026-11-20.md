# Scout’s View — opt-in proposal, 20 November 2026

**Proposal only.** No Scout page, monitoring rule, notification, action, or customer-facing preference is enabled by this document. Paul’s earlier request was to review Scout’s View after the four specialist page designs; this package prepares the decision for that next review.

## Suggested first-use choice

Keep the five core areas: Scout’s View, Profit Engine, Growth & Marketing, Cash Control and Plan. On the first entry to Scout’s View, offer a short choice:

- **Show Scout’s priorities** — build the page from currently supported evidence and explain each source.
- **Keep my current overview** — stay on the existing CFO Briefing without changing settings.

The choice should be reversible in Settings. Merely opening the page must not enrol the user in scheduled monitoring, share data with a new provider, save an action, or change an advertising or financial setting.

## Page job

Within ten seconds, show at most three matters that need attention, why each matters, and one safe next step. Use evidence from reviewed Profit Engine, Cash Control, Growth & Marketing and Plan. Link to the relevant calculation and source in **Explore the Numbers**. Do not reproduce all specialist cards.

The four questions remain:

1. What changed?
2. Why does it matter?
3. Where does the current path lead, if a supported scenario exists?
4. What is the next useful action?

Cash availability, working capital and stock funding must stay separate from EBITDA. A Plan result is a what-if assumption, not a forecast or realised saving. Marketing synthetic customer figures remain explicitly fictional. A “no supported issue” message must not become an all-clear.

## Evidence states and safeguards

- Show a priority only when the required period, source version, comparison and calculation are supported.
- For missing, stale, loading, failed, invalidated or mixed-company evidence, use a short state message and a link to repair or inspect it; do not substitute a sample.
- Keep evidence date and comparison period beside each claim. Preserve company/date selection when navigating to a specialist page and back.
- Rank by supported scale and urgency only. When evidence is incomplete, leave items unranked or state that priority is unknown; do not infer likelihood or causation.
- Recommendations describe analysis or a user-controlled test. No spend change, scenario acceptance, action save, reminder or automatic monitoring follows a click.

## Acceptance before implementation

Paul should review a low-fidelity wireframe showing (a) supported evidence, (b) one incomplete source, and (c) no supported priority. Then check the ten-second rule, mobile order, language, choice persistence and navigation to one specialist calculation. Only after that design decision should implementation add an opt-in preference or alter the overview. Any recurring monitoring, notification delivery, shared action persistence or automatic choice remains a separate feature and review.
