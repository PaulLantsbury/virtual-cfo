## Local metadata preparation helper

`prepareShopifyDailyReadiness` in `shopify-daily-readiness.mjs` accepts non-secret provider/database receipts, configured environment **names**, and actual current time. It reuses the existing runner's plan; it does not implement a duplicate runner or read secrets. It checks fresh (one hour) safe receipts, exact target/profile/cap, scope allowlist, disabled unused row and remaining future windows. It returns a disabled config plus concrete blockers. All operational authority/resource verification flags remain false: supplied receipts are preparation inputs, not authenticated runtime grants.

Required secret/configuration names checked by the helper: `NIGHT_SCOUT_TEST_PROGRAMME_DATABASE_URL`, `NIGHT_SCOUT_TEST_WRITER_SHOPIFY_CLIENT_ID`, `NIGHT_SCOUT_TEST_WRITER_SHOPIFY_CLIENT_SECRET`, `NODE_EXTRA_CA_CERTS`. The generator also needs its existing exact project/target/verified-target bindings and private config path. Name presence does not validate a value or prove an installation.

Local check: `node --test experiments/test-programme/shopify-daily-readiness.test.mjs` (four tests). Wrong target, stale/future evidence, unsafe scopes, non-development shop, existing actions, wrong cap/profile and absent RPC all block preparation. Source review and tests establish that the helper cannot mint a token, call a provider, write, enable or install a schedule.
