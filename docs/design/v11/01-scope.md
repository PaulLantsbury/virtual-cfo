## Design and implementation status

“Final design” means the authorised layout and behaviour are settled for this handoff. “Conditional workflow state” means a target design to build after the required service, permissions or persistence exist. In the current build, an unsupported control must be unavailable with an explanation. Design examples must never masquerade as working features or actual store results.

The image gallery uses the approved dark visual identity. Build semantic responsive components, auditable calculations and data-driven charts; do not use the screenshots as backgrounds. Written numerical fixtures define exact values and chart scales. Raster artwork is a visual reference rather than a calculation engine.

## Priorities

| Priority | Meaning |
| --- | --- |
| P0 | Trust, mathematical correctness, data scope, permissions and truthful availability. Required before the affected feature ships. |
| P1 | Core owner experience, disclosures, actions and complete workflow states. Build behind the necessary data foundations. |
| P2 | Later enrichment such as richer saved comparisons, paid-traffic models or cash forecasting. Separate data and release gates apply. |

## Scope boundaries

Signed-in product designs only. Pre-login sales, pricing and authentication mockups are excluded. The commercial approach remains documented because it affects feature access. No deployment, messages to customers, ad changes, repricing or accounting writes are part of this design task.
