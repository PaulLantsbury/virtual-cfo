# Night Scout approved design baseline v11

Start here for the approved signed-in page designs. Version 11 was approved on 30 October 2026. It contains the final 33 mockups and the complete specification text from the reviewed Word document.

## How development agents should use this package

1. Read [mandatory principles](00-principles.md), [scope](01-scope.md), [navigation](03-navigation.md), [shared page contract](04-shared-page-contract.md), and [period and per-order rules](04a-periods-and-per-order.md).
2. Read the relevant page specification below and open both its default and expanded images. Treat images as layout references; use the written definitions and full-precision fixtures for implementation.
3. Reconcile financial work with [agreed financial definitions](../../agreed-financial-definitions.md). Do not silently resolve a genuine conflict by changing an approved calculation. Record the conflict and request a decision when necessary.
4. Implement within the latest development handover's priorities and existing deployment/data safeguards. Design approval does not mean implementation, live data, persistence or notification services are available.
5. In the development handover or PR description, name the requirement IDs addressed, mockups consulted, relevant acceptance checks and any remaining differences. Verify the interface at the specified desktop/mobile sizes; screenshots alone do not prove ten-second comprehension.

## Authority and maintenance

This package supersedes earlier page-layout proposals within its signed-in design scope. It does not supersede the latest operational evidence, financial safeguards or deployment approvals. Reliable daily data and reader acceptance remain ahead of redesign work in the current handover; broader CFO recommendations remain deferred.

The Markdown files are the working development source of truth from this baseline onward. Preserve v11 as the approved snapshot; record later approved changes in a new version and update the starting-point links. Regenerate the Word review copy from the same approved text and images when publishing a new version. Do not independently edit two conflicting versions.

All mockup figures are fictional. The historical, planner and alternative-state examples have separate scopes. Exact financial definitions and acceptance criteria govern chart implementation; do not transcribe approximate raster chart geometry as data.
