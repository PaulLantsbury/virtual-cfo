# One approved private collection attempt

This source is default-off and has not executed a provider or database operation. Run only after the exact candidate is published, its commit is approved, account selection is complete, and the selected collector role/credential is separately approved. No scheduling, automatic retries, new advertising spend or date substitution is provided.

From a clean checkout of that exact commit, the named operator uses an absolute trusted Node binary, minimal reviewed executable path and operator home:

```
env -i PATH="$approved_node_path" HOME="$approved_operator_home" "$approved_node_binary" deployments/provider-activation/collection-cli.mjs --execute "$approved_binding_file"
```

Do not enable shell tracing or inherit `NODE_OPTIONS`/APM variables. The approved binding file is a canonical absolute private path, never a credential argument. Without arguments the command prints only `disabled`. The CLI rejects dirty/untracked checkout state and compares HEAD to the approved SHA. No provider configuration is inherited from the operator shell: inherited NIGHT_SCOUT variables are rejected, alongside the host boundary's foreign/admin credential checks. An independently approved private 0700 directory and 0600 owner-only regular files are mandatory; use canonical absolute paths, with no symlinks.

The private binding JSON contains exactly one provider (`meta` or `google`), `targetId` equal to the pinned staging project, approved `sourceSha`, `approvalRef`, `retryOrdinal:0`, `storeId`, `connectionId`, `currency`, `timeZone`, `from`, `to`, `environmentFile`, and `privateDirectory`. Meta requires `accountId`; Google requires `customerId` and explicit `loginCustomerId` (null for direct access). Account identifiers remain private. Dates must be 1–14 inclusive completed days in that account's time zone; Meta additionally enforces the 37-month lookback. No current day or substituted date is accepted.

The private environment JSON has `values`, `secretFiles`, `databaseCredentialFile` and `databaseConnection`. `values` maps the selected provider's non-secret runtime settings and exact approved bounds to strings. It must include staging runtime/project/store, all three collector/runtime/acceptance switches true, acceptance store/from/to and retry ordinal string `0`. Existing runtime-specific version/redirect/client metadata is required without changing its existing pins. `secretFiles` maps the allowed selected-provider environment names to canonical private files holding the exact raw value (avoid trailing newline for keys/secrets). CA PEM and envelope master key use private references; Google additionally needs its client secret. Inline database URLs, secrets, master keys and CA PEM are rejected.

`databaseCredentialFile` points directly to the access lane's delivered `<provider>-collector.credential.json`; no manual password copying is needed. Its version/provider/capability/exact role are checked, then a pinned PostgreSQL URL is built only in memory. The collector runtime independently checks the pinned database endpoint, CA and actual session/current role. Set `databaseConnection` explicitly to `direct` or `session-pooler` (omission defaults to direct). Direct uses the pinned database host and exact collector role; session-pooler uses the existing pinned `aws-1-eu-west-1.pooler.supabase.com`, port 5432 and project-qualified collector role. Neither mode falls back automatically; arbitrary hosts, transaction pooling or role overrides are not supported.

Before constructing a runtime, the wrapper exclusively creates and syncs `collection-attempt.json` in the private directory. It never deletes or overwrites that marker. Existing markers stop execution; do not remove one to retry. Uncertain outcomes require inspection and new explicit approval. The CLI also creates an exclusive private `collection-output.log` and captures runtime stdout/stderr there. Public output contains only state and coverage counts, or a fixed failure message. `already_running` exits nonzero. The private `collection-receipt.json` contains the approved binding, source and detailed result (including dates/run ID) when finished; errors produce an uncertain receipt. A crash can leave only the marker/output: treat that as uncertain too. Files are not collected or printed into ordinary logs.

The wrapper uses existing collector runtimes and idempotency keys (`meta_accept` / `google_accept`, unchanged date/account components, `r0`). Google reuses `runGoogleAdsAcceptance`. Meta validates returned date coverage, amount shape and complete/partial consistency. Active selected lineage is compared before collect, and the actual selected-account RPC inside each collector is guarded again before credentials/provider access, including Google's manager login, currency and time zone. No arbitrary account override is passed to the provider. A single invocation can call collect at most once; normal bounded pagination is part of that one existing collector attempt.

Acceptance evidence distinguishes an empty/no-observation test from positive-spend reconciliation. For Google, the owner has no historical-spend account; no spend creation or request for one follows from this procedure. After collection, separately authorized capability reads must verify attempt/observation persistence and the member report/pages. Keep the private evidence until the owner approves cleanup; do not delete history or remove attempt markers automatically.

Validation: fake-runtime and private-filesystem tests cover lineage drift, account-local date/source/target/ordinal rejection, late selected-RPC drift, both provider paths, capability credential parsing, contradictory Meta coverage, private modes/symlinks and exclusive markers. They perform no real provider calls, credential generation or database operations. The CLI's real execute path remains gated on an approved clean published checkout and private bindings.
