Prepared on04f1d5f with the exact imported384c2a9 engine/adapter. Frozen engine and pure history-cfo-analysis adapter are unchanged. No model module, feature flag, external request or model configuration is imported.

GET `/api/history-reporting/analysis` requires the existing bearer and exact currency, edition, from, storeId, to, versionId query. No browser authority/freshness/prior assertions are accepted. The optional service method verifies Auth and membership, opens the existing repeatable-read read-only transaction, verifies the current exact sealed selection using existing context/horizon/revision guards, then resolves only the immediately previous calendar month. Its authoritative selected head (or base seal when no head exists) passes those same checks. There is no latest-period guess, fallback to an invalidated prior base, extra query on ordinary history calls, cache or raw packet response.

Response `history-cfo-analysis-response-v1` has scope(storeId,currency,from,to,timezone), sourceBasis(synthetic-local), current/prior bindings or null, and analysis (the frozen cfo-analysis-v1 deterministic presentation). Each binding has financialVersionId, salesRevision, costRevision, observedAt, from, to; shared store/currency/timezone is inherited from the envelope. Original observation timestamps remain unchanged. Current unavailable means no facts; prior unavailable retains separately valid current facts but no comparison/investigation. “Current” freshness asserts a still-valid selected source revision checked in this read, not recent provider collection. Missing/tampered seals or withdrawn selections do not receive a browser freshness override.
