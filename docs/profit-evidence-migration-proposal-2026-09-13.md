## Proposed contract

All five new tables live in existing private `finance_v1`:

- `profit_evidence_versions`: selected store, complete calendar month, currency, contract version, source manifest and verifier/evidence references. IDs are supplied by the controlled writer; no implicit latest version selection exists.
- `line_cost_evidence`: references existing order/line IDs, observed full line snapshot, original quantity/date and evidenced historical landed unit cost in pence. This supplies currently missing historical facts without rewriting current variant cost. Old sale lines may be included to support later returns.
- `stock_return_evidence`: independently dated, positive saleable quantity referenced to historical line evidence. No refund-date fallback. Within a version, total returned quantity cannot exceed original quantity and cannot predate sale or follow the version's reporting end. Include prior returns in the manifest to validate cumulative recovery; later reader selects actual recognition month.
- `expense_evidence`: references existing `overhead_entries` or `marketing_channel_daily_metrics` rows and observed snapshots; contains no independently editable expense amount. Explicit reporting classification and currency must match scope. Complete-month actual, nonnegative overhead entries only; daily advertising inside that month. Other intervals, estimates and negative credits are outside this initial supported subset. `excluded_interest`/`excluded_corporation_tax` classifications support explicit exclusions.
- `profit_component_coverage`: separate booleans for historical cost, stock returns, variable expense, advertising, overheads and D&A, default false, with manifest/evidence reference. Inserting this row seals its version even if some components remain incomplete.

Row triggers reject update/delete, source/store/snapshot mismatches and writes to sealed versions. Version-row locking serialises inserts and seal checks within a version. Corrections require a new version, not rewriting prior evidence. Expense source identity and canonical expense key are unique per version; an evidence writer still must resolve actual cross-source equivalence rather than invent different keys for the same expense. Full snapshots deliberately become stale if their source records change.

No public source table is altered; existing id-only foreign keys are supplemented by insert-time same-store checks. Historical cost evidence requires matching source line quantity/order and same-store order; expense checks include category ownership. Current category inactivity does not silently remove historic amounts. Marketing currency cannot be checked from its raw table because the captured table lacks currency: it is an explicit evidence assertion matching the version, to be substantiated by the future writer/source documents.

All new tables have RLS enabled and no policies; PUBLIC/anon/authenticated/service_role have no table permissions from this proposal. The guard is SECURITY INVOKER with fixed search path and no client execution grant. There is no read RPC, external writer or elevated function. Existing sales access is unchanged. Database owners remain trusted administrators and can change schema/disable protections; these are not tamper-proof records against a database administrator.

## What disposable testing establishes

The test executes the exact proposal against the saved complete staging bootstrap in PGlite0.5.8, with a private empty finance schema. It passes schema compilation, full-month constraint, cross-store and currency rejection, historical line insert, independent April stock return against February sale, excessive return rejection, expense snapshot insert, duplicate source rejection, append-only rejection, sealing, authenticated read denial and absence of security-definer functions. One test group passed on13 September. This is neither concurrent-client testing nor live schema compatibility proof.

## Remaining before any application request

1. Agree concrete adapter-shaped manifest encoding with the calculation agent; current JSON objects are intentionally not sufficient standalone proof of completeness. Bind exact source rows/versions, sales evidence, expense authority and expected inventory. Include all relevant cumulative returns and detect omitted new rows.
2. Build consistent read/normalisation logic: recheck observed snapshots and source ownership every read, reject stale source/evidence, select independent stock events by saleable date and source expense amounts by approved scope, return component availability. Insert-time checks alone do not notice later source updates. Do not wire raw tables directly to actual reports.
3. Verify actual-only provenance, landed-cost/tax evidence and source equivalence in a controlled writer. A non-`estimated` string is not by itself verified marketing spend. Reject blank/unknown provenance unless evidence supports it; no blanket VAT conversion or invented credit policy.
4. Define active/superseding version selection and the snapshot transaction boundary. A newer version cannot silently inherit coverage; old versions must not masquerade as current. No version promotion mechanism is supplied here.
5. Prepare exact synthetic setup and reconciliation checks against the existing target, test replay/failure/concurrency and inspect current staging schema. Include a concrete rollback/recovery plan preserving existing source and review history; no DROP script for occupied evidence is proposed.
6. Apply only after those pieces form a concrete reviewed package and Paul gives separate staging database approval. Application reporting and scenario baselines then need their own integration and staging verification.

No unsupported allocator, FX, estimates, arbitrary-range expense totals, cash or live profit output is introduced. This proposal can be committed as a tested foundation while the remaining reader/setup work continues under the agreed scope.

## Disposable read projection added in this package

`experiments/financial-v1/profit-evidence-reader.mjs::readProfitEvidence` now projects the proposed storage into the pure `profit-evidence.mjs` contract inside one repeatable-read, read-only transaction. The caller must authorise store/version and supply a trusted `readSales(tx, scope)` adapter which validates existing sales evidence **inside that transaction** and returns validated sales, all eligible historical order IDs/dates through the cutoff, and a revision. The tests use an explicitly synthetic zero-sales callback that checks transaction settings. A real `finance_v1` sales callback/public RPC is not supplied or enabled; do not pass cached or client-provided sales.

The reader requires the same manifest in version and sealed coverage, validates inventory of source line IDs for selected-period orders and originals referenced by recoveries, expense source IDs against current overlapping actual overhead/daily-marketing rows, and recovery IDs. It checks observed source snapshots again. Amounts are read from SQL numeric `::text` into exact-pence parsing, not rounded through JSON floating point. Invalid expenses suppress affected expense components while preserving valid gross profit and sales; invalid line evidence suppresses product-cost components without deleting valid expense evidence. Structural version/scope/manifest failures withhold all cost evidence while preserving the separately validated sales object.

The explicit manifest format for this bounded reader is version1, `salesRevision`, `lineIds`, `returnIds`, `expenseSources`, `lineProofs` and `expenseProofs`. A line proof requires `historicalLandedCostSupported:true`, document reference and digest of the observed evidence row including current line snapshot. Expense proof requires actual basis, `taxTreatment:accounting_amount_supported`, evidenced currency, document reference and observed-source digest. These attestations must be substantiated by the controlled writer; the reader does not infer them from an evidence reference. Classification-specific D&A is included in overhead expense and added back once. Excluded tax/interest rows remain in source inventory but not profit expenses.

Extended disposable tests pass actual source overhead projection (GBP100 D&A gives operating loss100 and EBITDA0 in a synthetic zero-sales month), changed-source invalidation, newly omitted-source invalidation, sales/gross-profit retention during overhead failures and transaction settings. The reader also passes a nonzero historical-line projection using the exact SQL evidence digest: an April return of one February unit at GBP40 gives COGS−40, gross profit40, operating loss60 and EBITDA40 after GBP100 D&A overhead. Changing the original raw line quantity withholds COGS while retaining valid overheads and sales. A real mapped-sales callback still needs integration tests before live readiness. Cumulative physical warehouse history still requires attested complete source manifests because the saved schema has no independent warehouse event ledger. Remaining rollout items above are narrowed by this implementation, not eliminated.
