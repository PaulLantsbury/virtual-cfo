## Implemented here, and intentionally not implemented

`experiments/provider-proxy/boundary.mjs` is pure request/response preparation and validation. It imports no network, runtime, environment or credentials, registers no route and cannot forward a request. `APPROVED_PRIVATE_ORIGINS` is an empty frozen list; `providerProxyActivation()` always returns disabled/private_host_unpinned. There is no environment-supplied arbitrary URL escape hatch. This is not an operational proxy or end-to-end readiness claim.

`prepareProviderProxyRequest` accepts raw method/path/header/body input and produces only an exact path, selected headers/body and transport requirements. `projectProviderProxyResponse` accepts an already bounded upstream response, projects whitelisted headers/JSON shapes, suppresses callback HTML and normalises upstream errors to a fixed message. The private service still owns fresh Auth and owner/member/store authority. The pure proxy does not infer owner status from a bearer token or callback hint.

### Exact request contract

- Current public origin remains `https://night-scout-xero-staging.onrender.com`, matching the existing frozen runtime pins. No origin from Host/Forwarded/X-Forwarded-Host is trusted.
- Meta: POST connect/select-account/selection/cancel/disconnect; GET callback/selection/status.
- Google: POST connect/select-account/disconnect; GET callback/account-selections/status. No invented Google pending-cancel endpoint.
- `/api/meta-ads/spend` and `/api/google-ads/spend` are excluded and remain local report routes. All other paths, encoded/normalised path alternatives, trailing slash, unsupported method and arbitrary absolute URL are refused.
- Status/selection query contains only one valid storeId. POST query is absent; JSON has exact endpoint fields and flat string/null values, with duplicate and escaped-equivalent keys rejected before forwarding. Provider account and connection identifiers follow current router shapes.
- Callback permits only existing state/code/error keys, unique scalar values and current provider patterns. It forwards no browser bearer/cookie. Callback state validation/consumption stays private-server owned.
- POST must have the exact website Origin and JSON content type. Noncallback requests require a bounded bearer credential. Only Authorization, JSON Accept, necessary POST Origin/Content-Type and the matching provider selection cookie are forwarded. Host, X-Forwarded-*, tracing, unrelated browser cookies and extra headers never forward.
- Limits: raw path/query 8192 UTF-8 bytes, body 8192 bytes, bearer 8192 bytes, input cookie header 16384 bytes. The eventual HTTP adapter must enforce these **before buffering**. Relevant duplicate headers/selection cookies and CR/LF/NUL are rejected.

### Exact response/transport contract

- Required transport: fixed approved private origin only, append validated path; no request-supplied origin/port/path base, credentials in URL, query-based target, DNS wildcard or alternate host. No automatic redirect following or retries. An overall 15-second deadline and maximum 1 MiB streamed response must be enforced by the future transport, including aborted/downstream-closed requests. These are emitted policy requirements, not claimed implemented timers/stream bounds in the pure functions.
- Forward only exact provider `Set-Cookie` values: correct host-only name/path, Secure, HttpOnly, SameSite=Lax, 900-second selection handle or exact zero-age expiry. No Domain, unrelated cookie, extra attribute or combined cookie list. Only routes that legitimately set/clear selection cookies may return them. Browser cookies remain on the website, not a private/public alternative origin.
- Only callback status 303 with exact relative Settings destinations is preserved: Meta `?metaSelection=select`/`?metaConnect=cancelled`; Google `?googleAds=select`/`?googleAds=cancelled`. No absolute/open redirect or extra parameters. Callback upstream HTML is discarded.
- Returned headers are no-store/private, no-referrer, nosniff and JSON; safe cookie/location exceptions above. Upstream status errors return generic JSON, no error text/SQL/credential/header echo. Successful JSON has exact top-level route shape and a bounded field-name whitelist; semantic account/status validation remains in existing private routes and frontend parsers. This boundary is not a new replacement provider service validator.
- No logger or telemetry exists in this module. The final HTTP adapter must likewise avoid request bodies/query/header/cookies, upstream URLs and error objects in logs. Platform ingress/forwarding/outbound instrumentation/exports/retention remain separately attested; local source policy does not prove them safe.
